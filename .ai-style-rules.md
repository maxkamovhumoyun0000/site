# Diamond Site style rules

Scan: medium repository (329 tracked source files), baseline `dbc2bac`.

## Golden Files

- `app/ui/study-room-chat.tsx` — client components keep API loading, local
  busy/notice state, and rendering in one feature-owned component; web UI uses
  `premium-card`, `btn`, `text-ink-*` and `dark:text-navy-*` tokens.
- `app/ui/weekly-study-plan.tsx` — async data actions use `try/finally`, retain
  existing state on background refresh, and use the `useWebT` fallback form.
- `backend/personalization.py` — additive routes/tables live in the feature
  router; bearer authentication and role checks always precede data access;
  DB connections are closed in `finally`.

## Naming & State-Control Rules

- React client components use `Row = Record<string, any>` for backend payloads,
  `loading`, `busy`, and user-facing `notice`/`error` state.
- Use `apiFetch` supplied by the shell rather than a second web HTTP client.
- Preserve the existing token system in all new web UI: `premium-card`,
  `border-line`, `bg-surface-soft`, `dark:*`, and `useWebT(key, fallback)`.
- API mutations validate identity/role first, call `ensure_schema()` for
  additive data, and use parameterized SQL. Sensitive flows have an opaque
  token rather than a numeric user id in public URLs.
- New contracts are backward-compatible and low-cost: list payloads omit
  large content; details are fetched only after the user opens them.

## DONTs

- Do not replace the web design system with generic Tailwind palettes or a
  standalone page layout that ignores dark mode.
- Do not add unauthenticated staff/student mutations or trust client-side
  locking for Learning Path progression.
- Do not create a parallel API client, duplicate auth policy, or use direct
  SQL string interpolation for user data.
- Do not change unrelated dirty worktree files merely to make a feature look
  cleaner.
